CAHIER DES CHARGES COMPLET — L’IMPTEBISIBLE1.9CHAT

Version : 1.0
Type : Application mobile Android
Nom : L’Imptébisible1.9Chat
Langue : Français
Plateforme principale : Android
Objectif : Application de messagerie permettant à deux téléphones ou plusieurs utilisateurs de communiquer réellement via Internet

---

1. OBJECTIF DU PROJET

Créer une véritable application mobile Android de messagerie appelée L’Imptébisible1.9Chat.

L'application doit permettre à plusieurs utilisateurs possédant chacun leur compte de communiquer entre eux en temps réel.

L'application doit fonctionner avec un véritable backend et une véritable base de données.

Je ne veux pas d'une simple maquette, d'une démonstration ou d'une application contenant uniquement des données fictives.

Les fonctions doivent être réellement connectées au serveur.

L'application doit notamment permettre :

- créer un compte ;
- se connecter ;
- rechercher un utilisateur par numéro de téléphone ;
- ajouter des contacts ;
- discuter avec un contact ;
- envoyer et recevoir des messages ;
- envoyer des photos ;
- envoyer des vidéos ;
- envoyer des documents ;
- enregistrer et envoyer des messages vocaux ;
- recevoir et lire les messages vocaux ;
- créer des groupes ;
- participer à des groupes ;
- publier des statuts ;
- effectuer des appels audio ;
- effectuer des appels vidéo ;
- recevoir des notifications ;
- gérer son profil ;
- bloquer et débloquer des utilisateurs ;
- gérer les paramètres de l'application.

2. RÈGLE IMPORTANTE SUR L'INSCRIPTION

AUCUN OTP POUR LE MOMENT

Ne mets aucun système de code OTP par SMS.

Ne mets pas non plus de vérification obligatoire par code envoyé par e-mail.

L'inscription doit être directe.

L'utilisateur doit pouvoir créer son compte avec :

- Nom ou pseudo ;
- Numéro de téléphone ;
- Mot de passe ;
- Confirmation du mot de passe.

Exemple :

Nom d'utilisateur : Koffi
Numéro : 0545312901
Mot de passe : ********
Confirmation : ********

Après validation, le compte est créé directement si les informations sont valides.

Afficher ensuite un message de réussite et permettre à l'utilisateur d'accéder à son compte.

Le numéro de téléphone doit être enregistré dans la base de données.

---

3. NUMÉRO DE TÉLÉPHONE

Le numéro de téléphone est l'identifiant utilisé pour retrouver les utilisateurs.

L'utilisateur doit pouvoir rechercher un autre utilisateur avec son numéro.

Exemple :

Utilisateur A possède :

0545312901

Utilisateur B possède :

0500000000

Depuis le téléphone A, l'utilisateur peut rechercher :

0500000000

L'application doit alors afficher le profil correspondant, si ce compte existe.

L'utilisateur peut ensuite :

- ajouter la personne ;
- ouvrir une conversation ;
- envoyer un message.

La recherche doit être effectuée côté serveur.

Ne jamais utiliser uniquement une liste locale fictive.

10. TEMPS RÉEL

La messagerie doit fonctionner en temps réel ou quasi temps réel.

Lorsqu'un utilisateur A envoie un message à B :

A → serveur → B

Le téléphone B doit recevoir le nouveau message sans devoir actualiser manuellement la page.

Utiliser une technologie adaptée au temps réel, par exemple WebSocket ou une solution équivalente.

11. MESSAGES VOCAUX

Créer une fonction de message vocal.

L'utilisateur doit pouvoir :

1. maintenir ou utiliser le bouton microphone ;
2. demander l'autorisation du microphone ;
3. enregistrer sa voix ;
4. arrêter l'enregistrement ;
5. écouter le vocal avant l'envoi si possible ;
6. envoyer le vocal ;
7. permettre au destinataire de le recevoir ;
8. permettre au destinataire de l'écouter.

AUTORISATION MICROPHONE

L'autorisation Android doit fonctionner correctement.

Si elle n'est pas accordée :

Afficher clairement :

L'accès au microphone est nécessaire pour enregistrer un message vocal.

Prévoir un accès aux paramètres Android lorsque l'autorisation a été refusée définitivement.

Ne pas considérer l'autorisation comme accordée sans la vérifier réellement.
